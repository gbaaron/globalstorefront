Architecture, made visual

How Global Storefront actually fits together

One codebase, several "front doors," and two kinds of database. This page shows you who sees what, and where every piece of data lives — based on the real files in this repo.

The 10-second version: There is one admin app (app.html). The iOS app is just that same app wrapped in a native shell. The "web" and "mobile web" versions are the same page in a browser — they only lose the native extras (push, vibration, badge).

Customers never touch Global Storefront's site. They go straight to the individual company's own site (e.g. Zeeland Bakery). The only Global Storefront thing on that site is the chat bubble.

The data is split. Global Storefront's database holds the client list + all chat/bot data. Each company (Zeeland) has its own separate database for its orders and products.

iOS app vs. web vs. mobile web — for the admin

This is the part that feels like three things. It's really one thing in three wrappers.

🧩 It's the exact same app.html every time

The store-owner's admin app — Home, Inbox, Orders, Analytics, Settings — lives in a single file, app.html. Nothing about that file changes between platforms. What changes is the shell around it.

Native iOS / Android app

Capacitor wraps app.html in a real native app and points it at the live URL. A second file, native-bridge.js, switches ON the native powers:

  • Push notifications (new customer message → buzzes your phone)
  • Haptics (vibration on new message)
  • App-icon badge (unread count)
  • Native status bar / splash screen

Browser Mobile web admin

Open app.html in your phone's browser and you get the identical dashboard — same tabs, same data.

  • native-bridge.js sees it isn't inside the app, so push / haptics / badge become harmless "do-nothing" stubs
  • Everything else works exactly the same
  • This is the fallback when someone hasn't installed the app

Browser Desktop web admin

Same app.html again, just on a bigger screen. The layout is responsive, so it stretches out.

  • Good for managing orders at a laptop
  • Still no phone-only features (push/buzz/badge)
  • No separate "desktop build" exists — it's the same page

The one branching rule: where does logging in actually send you?

The native app is the "manage my store" door. A plain browser login is the "go look at my store" door.

🛠️ One more admin surface: the agency dashboard (admin.html)

Don't confuse this with the owner app. admin.html is your control panel (the agency / Aaron). It's where you add clients, fill in each store's Bot Knowledge, and run the Test Bot. Store owners never see it. It's a desktop-web tool, not part of the iOS app.

What about the customer (the shopper)?

Your instinct was right: there is no Global Storefront "user version." They go straight to the company.

A customer question travels left → right (watch the dot)

The bot handles the easy 80%. Only the questions it can't answer buzz the owner's phone.

📱 Is there a mobile vs. desktop customer version?

No separate versions. The customer just sees the company's website, which is responsive on its own. The chat widget is also responsive — same single widget on phone and desktop. There's no "Global Storefront app" for shoppers to download.

🏪 So where does Global Storefront live, for a customer?

Effectively invisible. It quietly powers the chat bubble and routes messages to the owner. The shopper experiences "Zeeland Bakery," not "Global Storefront." The Global Storefront branded site (index.html) is a sales/login page for owners — customers don't go there.

Every client gets their own separate base. Sushi GoGo has a different one, the barbershop another, etc. Their orders & products live only here — not in the Global Storefront base.
How the two connect: Each row in the Global Storefront Clients table has a BaseID field pointing at that company's own base. When the owner opens the Orders tab, get-tenant-admin.js reads their BaseID and reaches into Zeeland's base to fetch orders. One function, but it routes to the right company's database every time.

One app, one API — but every business keeps its own separate database

Add a client → they get their own database. The app never gets rebuilt; the API just routes to the right one.

So does Zeeland's customer data end up in the Global Storefront database?

Partly — and this is the subtle bit. It depends on what kind of data.

Same shopper, two different actions, two different destinations

An order goes to Zeeland's own database. A chat message goes to the shared Global Storefront database.

Stays with Zeeland Business / transaction data

  • Orders a customer places → Zeeland's own base
  • Products / menu items → Zeeland's own base
  • Appointments → Zeeland's own base

This never lands in the Global Storefront database. Global Storefront only reads it on demand to show the owner their numbers.

Goes to Global Storefront Chat / bot data

  • Conversations a shopper has with the bot
  • Messages, including the customer's name/email if they give it
  • Bot logs of what was asked & answered

All of this is written into the shared Global Storefront base, tagged with a TenantID so each business only sees its own threads.

Plain-English summary: A shopper's order goes to Zeeland's database. A shopper's chat message goes to Global Storefront's database. The bot data of every business is pooled in the one shared hub (separated by tenant tag), while the money/inventory data stays private in each business's own base.

Your exact questions, answered

What's the difference between the iOS app and the web / mobile web version for admins?
Almost none in terms of screens — they all run the same app.html. The difference is powers: the iOS/Android app adds push notifications, vibration, and an unread badge via the native shell. The web and mobile-web versions are the same dashboard minus those phone-only features.
Is there a user (customer) version of the site, or do they go straight to the company?
They go straight to the company (e.g. Zeeland Bakery's own website). There is no Global Storefront customer app or customer login. Global Storefront's only presence for a shopper is the chat bubble injected onto the company's site.
Is there a separate mobile-web vs. regular-web version for customers?
No. The company's website is responsive by itself, and the chat widget is responsive too. Same single experience whether on a phone or a laptop.
Is all the data in one database for Global Storefront, regardless of the business?
No. The Global Storefront base holds the client directory + all chat/bot data for everyone. But each business has its own separate database for its orders, products, and appointments. Two layers, linked by a BaseID.
Does user data for other companies (e.g. Zeeland) go to the Global Storefront database?
Chat data does; business data doesn't. When a shopper talks to the bot, that conversation (and any name/email they share) is stored in the Global Storefront base. But when that same shopper places an order, it goes into Zeeland's own base — Global Storefront never stores it.
